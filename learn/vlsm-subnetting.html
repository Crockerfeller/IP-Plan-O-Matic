VLSM subnetting, explained with an example

Variable Length Subnet Masking (VLSM) gives every network the size it actually needs, instead of cutting the whole block into equal pieces.

Why not equal-sized subnets?

Splitting a /22 into four /24s gives each network 254 hosts. That wastes most of a /24 on a 10-host management network and doesn’t leave room for a 300-host network at all. VLSM sizes each subnet separately.

The method

  1. List each network with its host count, and add growth headroom if you expect it to grow.
  2. For each one, pick the smallest prefix whose usable hosts cover the need (see how many hosts).
  3. Sort largest first and place each one at the next free address that is aligned to its size. Largest first keeps everything aligned without gaps.
  4. Whatever is left over stays free for later.

Worked example: seven networks in 10.10.0.0/22

The plan uses 564 of 1,024 addresses (55%). Left free: 10.10.2.52/30, 10.10.2.56/29, 10.10.2.64/26, 10.10.2.128/25, 10.10.3.0/24, ready for new networks later.

Placing largest first is what keeps VLSM simple. Each subnet must start on a multiple of its own size (a /26 on .0, .64, .128 or .192), and big blocks first means the next free address is always correctly aligned for the next, smaller block.

Adding networks to an existing plan

When some subnets are already in use, put new ones in the smallest free gap that fits instead of starting over. IP Plan-O-Matic’s Auto-plan tab does this with Fill free space, keeping the subnets you already named or marked in use.
