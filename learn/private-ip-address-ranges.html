Private IP address ranges and special-purpose blocks

Which IPv4 and IPv6 ranges are private, which are reserved, and which ones cause trouble when networks meet.

IPv4

RangeWhat it isNotes
10.0.0.0/8Private (RFC 1918)The largest private block. Common for enterprises and clouds.
172.16.0.0/12Private (RFC 1918)172.16.0.0 to 172.31.255.255. Docker’s default bridge uses 172.17.0.0/16 and the AWS default VPC 172.31.0.0/16.
192.168.0.0/16Private (RFC 1918)Home and small office routers. 192.168.0.0/24 and 192.168.1.0/24 clash with almost every home network on a VPN.
100.64.0.0/10Shared address space, CGNAT (RFC 6598)Used by ISPs for carrier-grade NAT and by some overlay networks. Not for your LANs.
127.0.0.0/8LoopbackThe host itself. 127.0.0.1 is the usual address.
169.254.0.0/16Link-local (RFC 3927)Self-assigned when DHCP fails. Cloud metadata services also live at 169.254.169.254.
192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24Documentation (RFC 5737)For examples in docs and training. Never routed.
198.18.0.0/15Benchmarking (RFC 2544)For network device testing.
224.0.0.0/4MulticastGroup traffic. Not assignable to hosts.
240.0.0.0/4ReservedFormerly “class E”. Not usable on most systems.
0.0.0.0/8“This network”0.0.0.0 means “any” or “unknown”.

IPv6

RangeWhat it isNotes
fc00::/7Unique local, ULA (RFC 4193)The IPv6 equivalent of private space. Use fd00::/8 with a random 40-bit ID.
fe80::/10Link-localEvery IPv6 interface has one. Used for neighbor discovery and routing protocols.
::1/128LoopbackThe host itself.
2001:db8::/32Documentation (RFC 3849)For examples. Never routed.
64:ff9b::/96NAT64 well-known prefix (RFC 6052)IPv4 addresses embedded in IPv6 for NAT64.
ff00::/8MulticastIPv6 has no broadcast; multicast replaces it.
2000::/3Global unicastPublic IPv6 addresses.

Choosing ranges that won’t clash later

  • Avoid 192.168.0.0/24 and 192.168.1.0/24 for anything users reach over a VPN: their home router almost certainly uses the same range.
  • Avoid 172.17.0.0/16 if Docker runs anywhere nearby, and 172.31.0.0/16 if you will peer with AWS default VPCs.
  • Give every site and VPC its own block from one master plan (for example, a /16 per region out of 10.0.0.0/8). Overlaps are painful to fix once VPNs, peering or mergers connect the networks.
  • For IPv6, generate a random ULA /48 instead of picking fd00::/48, so two organizations are very unlikely to collide.
