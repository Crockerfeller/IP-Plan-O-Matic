AWS VPC subnet sizing

AWS reserves 5 addresses in every subnet and limits sizes to /16 through /28. Here is what that means for your plan.

The 5 reserved addresses

In a subnet such as 10.0.0.0/24, AWS keeps:

  • 10.0.0.0: the network address
  • 10.0.0.1: the VPC router
  • 10.0.0.2: the Amazon-provided DNS server
  • 10.0.0.3: reserved for future use
  • 10.0.0.255: the last address (AWS doesn’t support broadcast, but reserves it)

Size limits

A VPC’s IPv4 CIDR block and each subnet must be between /16 (65,536 addresses) and /28 (16 addresses). You can add secondary CIDR blocks to a VPC later, but you can’t resize a subnet, so size generously up front.

A three-AZ layout

Each subnet lives in one Availability Zone, so most designs repeat every tier in each AZ. Here is a 10.20.0.0/16 VPC with public, private app and database tiers across three AZs, sized largest first:

That uses about 22% of the /16, leaving plenty of room for more tiers or AZs.

Tips

  • Private subnets need the most room. With the default Amazon VPC CNI, each EKS pod takes a VPC address, and load balancers, endpoints and Lambda functions in a VPC use addresses too.
  • Plan for peering and Transit Gateway from day one. Connected VPCs and on-premises networks can’t overlap.
  • Leave the default VPC (172.31.0.0/16) alone and don’t reuse its range for VPCs you’ll connect.
