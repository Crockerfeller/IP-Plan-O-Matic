Azure VNet subnet sizing

Azure reserves 5 addresses in every subnet, and some Azure services need dedicated subnets of a minimum size.

The 5 reserved addresses

In 10.1.0.0/24, Azure keeps 10.1.0.0 (network), 10.1.0.1 (default gateway), 10.1.0.2 and 10.1.0.3 (Azure DNS) and 10.1.0.255 (broadcast).

Sizes

The smallest IPv4 subnet is a /29, which leaves just 3 usable addresses.

Subnets Azure services need

Subnet nameUsed bySize
GatewaySubnetVPN and ExpressRoute gateways/27 or larger recommended
AzureBastionSubnetAzure Bastion/26 or larger
AzureFirewallSubnetAzure Firewall/26

These subnets must use exactly these names. Plan them into the VNet before filling it with workload subnets.

Tips

  • AKS with traditional Azure CNI gives every pod a VNet address, so those subnets get large quickly. Overlay networking avoids that.
  • Peered VNets and on-premises networks can’t overlap. Carve every VNet from one master plan.
  • Subnets can be resized only while empty, so leave growth room.
