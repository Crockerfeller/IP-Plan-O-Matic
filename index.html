Auto-plan prefixes by count

One line per group: Name, /length, count. For example Sites, /56, 12 or Branch LANs, /64, 40. Count defaults to 1. Prefixes are placed largest first in the smallest free space that fits, split on nibble boundaries where possible.

About IP Plan-O-Matic

IP Plan-O-Matic is a free subnet calculator and IP address management (IPAM) planner for network engineers, sysadmins, cloud architects, homelabbers and CCNA students. Instead of calculating one subnet at a time, you lay out a whole address plan: start from a block such as 10.0.0.0/16, divide it into halves as many times as you need, and join neighbors back together by clicking the colored bars.

  • IPv4 subnet planner: network, broadcast, usable range, gateway, netmask, wildcard mask, binary and host count for every subnet, on a color-coded address map, with undo and redo.
  • Several base networks: keep HQ, branch and cloud ranges in one plan, each with its own platform rules; overlaps between them are refused.
  • VLSM calculator: list networks with host counts (and optional VLANs and growth headroom) and get a packed, overlap-free plan, or fill only the free space around subnets you already have.
  • Cloud rules: AWS VPC, Azure VNet, Google Cloud VPC and Oracle Cloud (OCI) VCN reserved addresses and minimum subnet sizes.
  • Overlap checker and route summarization: check new plans against existing networks, VPN peers or VPCs, and collapse lists of routes into the fewest CIDR blocks or a single supernet.
  • Address info: RFC 1918 private, CGNAT, link-local, documentation, multicast and other special ranges, plus the reverse DNS (in-addr.arpa) zone.
  • IPv6 prefix planner: split a /48 or /56 by bit or nibble, give each prefix a name, VLAN, status and notes, auto-plan by count (like twelve /56s for sites), and generate a random ULA.
  • Saved plans and offline use: save named plans in your browser, export them as a backup, and install the app to use it without a connection.
  • Export: Cisco IOS / IOS-XE, Juniper Junos, MikroTik RouterOS, Terraform for AWS, Azure, Google Cloud and Oracle Cloud, CSV and JSON, with optional DHCP pools.

Accuracy and privacy

Every release is checked by an automated test suite that runs the real page in a browser. The subnet math is compared with Python’s ipaddress library on hundreds of random IPv4 and IPv6 networks and route lists, cloud reserved-address counts are checked for every platform, and random VLSM plans are verified to be aligned and overlap-free. The tests are public.

There are no ads, no analytics and no cookies, and you never need an account. Your plan stays in your browser: in the page link, and in local storage if you save it. The only outside requests are for the web fonts and the version number in the footer.

Frequently asked questions

How many usable hosts are in a subnet?

A /n subnet has 232−n addresses. On a standard network two are reserved (the network ID and the broadcast address), so a /24 has 256 addresses and 254 usable hosts, a /26 has 62, and a /30 has 2. A /31 point-to-point link uses both of its addresses (RFC 3021), and a /32 is a single host.

Why does AWS reserve 5 IP addresses in every subnet?

AWS reserves the first four addresses (network ID, VPC router, DNS, and one for future use) and the last address of every subnet, so a /24 in a VPC has 251 usable addresses. Azure also reserves five, Google Cloud four, and Oracle Cloud (OCI) three: the network ID, the gateway and the broadcast address. Pick the platform on the Plan IPv4 tab and the host counts, gateway and exports follow those rules.

What is VLSM, and how do I use the auto-planner?

Variable Length Subnet Masking gives each subnet a size that fits its needs instead of making them all equal. On the Auto-plan tab, list each network as Name, hosts (optionally , VLAN). The tool picks the smallest prefix for each and places them largest first, each in the smallest free space that fits. Replace the plan starts from an empty base network; Fill free space keeps the subnets you already named or marked in use. Then apply the result to the planner.

Is my network plan sent to a server?

No. All calculation happens in your browser. The plan is stored in the page address after the #, which browsers never send to the web server, so a bookmark or a copied link saves and shares the whole plan, names and VLANs included. Saved plans and the autosaved working plan stay in your browser’s own storage.

Does it work offline?

Yes. After your first visit the app is cached, so it opens and works without a connection. You can also install it from your browser’s menu (Install app, or Add to Home Screen on a phone).

What size IPv6 prefix should a LAN use?

A /64 is the standard size for a single LAN or VLAN, and SLAAC requires it. Sites typically receive a /48 or /56, which you split on nibble (4-bit) boundaries so prefixes stay readable and reverse DNS delegation stays clean. Point-to-point links often use /127.
